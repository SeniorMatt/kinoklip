### Equalizer editor
The graphical Equalizer (`src/ui/audio/EqCurveView.*`, `src/ui/inspector/ClipEqEditor.*`) follows the
look of free equalizer editors, which were studied for ideas only: Audacity's Filter Curve EQ (GPL-2.0-or-later: a plot with a
0 dB line, a labelled log frequency axis and dB grid, redraw on edit; its envelope-point editor itself
is not used because it draws a FIR envelope, not a parametric one), FL Studio-style filled total curve
with numbered band handles. No code from any of them was copied; the maths is Kinoklip's own RBJ biquads (`src/render/Biquad.h`).

### Merge and Transform controls
The extra apply modes of the Merge node (`src/render/CompMath.cpp`, `blendChannel()` / `blendColor()` and the
GLSL copy): Hue, Saturation, Color, Luminosity, Divide, Darker / Lighter Color, Average, Negation, Reflect, Glow,
Phoenix, Freeze and Heat. The non-separable four use the W3C Compositing and Blending specification; the others
are the common formulas that Natron's merge operators (GPL-2.0-or-later) and other open compositors list. They
were written from those definitions, no code was copied. The Normal operators (Over, In, Held Out, Atop, XOr) are
the Porter-Duff operators; the filter kernels (Catmull-Rom, Mitchell, cubic B-spline, Lanczos, Gaussian) are the
published Mitchell-Netravali family and the Lanczos window. The control names and the behaviour of Edges, Pivot,
Invert Transform, Alpha Gain, Burn In and Subtractive / Additive follow the Blackmagic Fusion manual.

### Masks and keyers (Compositing page)
The Luma Keyer, Delta Keyer, Corner Positioner, B-Spline mask, Rectangle Corner Radius and the mask Paint Modes
(`src/render/CompMath.cpp`, `lumaKey()`, `deltaKey()`, `cornerPositionerMatrix()`, `bsplinePolygon()`,
`paintMask()`; GLSL copies in `GlComposition.cpp`, `GlMasks.cpp`) take their control names and behaviour from the
Blackmagic Fusion manual. The formulas are our own: a difference key on the strongest screen channel with a
Gain / Balance / Clean / Threshold remap, a linear soft range for the luma key, the standard uniform cubic
B-spline basis (with point weights as a rational B-spline) and a signed-distance rounded rectangle. No code or
formula was taken from Natron, Kdenlive / MLT or any other project.

### Soft Glow and Light Wrap (Compositing page)
`src/render/CompFilterMath.*` and `GlCompFilters.*`. Soft Glow follows the control list of Fusion's Soft Glow
tool in the public Fusion reference manual (Filter, Threshold, Gain, Glow Size, Num Passes, Color Scale). The public
manuals describe no Light Wrap tool in Fusion; its control set (Intensity, Diffuse, Generate Wrap Only, Enable Glow,
foreground and background blur, Saturation, Luma Tolerance, luminance-based wrap, highlight merge, constant colour)
is that of the Natron `LightWrap` plugin's documentation (GPL-2.0-or-later); the implementation is our own, the
usual blurred-matte technique, no Natron code was copied. Blender's Glare node (GPL-2.0-or-later) was read for how
a glow's threshold, gain and size controls behave. The blur filters (box, Bartlett as two boxes, multi-box,
Gaussian) are the standard definitions.

### Grid Warp, Displace and Vector Distort (Compositing page)
`src/render/CompWarpMath.*`, `GlCompWarp.*`. Displace takes its control set from the public Fusion reference manual
(Type X/Y or Radial, per-axis channel, X / Y Refraction). The behaviour of a displacement map was checked against
Blender's compositor Displace node and Natron's IDistort / STMap (both GPL-2.0-or-later); the code is our own.
Grid Warp uses the Catmull-Rom grid field of Kinoklip's own Warper effect (`GlMeshEffects.cpp`).

### Keyers (Compositing page)
`src/render/CompMatteMath.*`, `GlCompMatte.*`: the Delta Keyer's advanced controls, the Ultra Keyer and Matte Control.
The control sets and their meaning follow the public Fusion reference manual (Delta Keyer, Ultra Keyer, Clean Plate,
Matte Control). Blender's compositor Keying node (GPL-2.0-or-later: pre-blur, clip black / white, dilate / erode,
feather, despill, screen balance) was read as the open-source counterpart for what a screen keyer does in what order.
The colour-difference key, the morphological and blur matte filters, the restore-fringe formula, the spill methods
and the fringe window are our own; no code was copied from Blender, Natron or any other project.

### Text+ layouts (Compositing page)
`src/render/TextPlus.*` places each glyph of the Text node at an arc length of a circle or a path, turned to the
tangent with its baseline on the curve; frame layout wraps greedily at the frame width. This is the usual
text-on-path layout; Glaxnimate's text-on-path (GPL-3.0-or-later) was read for how glyphs follow a curve. No code
was copied. The control list follows the Text+ tool of the public Fusion reference manual.

### Bezier mask, Roto Assist and mask tracking (Compositing page)
`src/compositing/RotoAssist.*` (Sobel edge snapping), `src/compositing/tracking/TrackFollow.*` (a track's move, turn
and scale applied to a node's keys or the points of a shape; reuses `matchmove::motionBetween()`). The feature set
(smooth and corner points, inserting a point on the curve, a mask that follows a tracker, snapping roto points to
edges) is common to Blender's mask editor and Natron's Roto (both GPL-2.0-or-later); their public documentation could
not be read in full while writing this, and no code was taken from either. The Bezier point maths reuses the Edit
page mask code (`core/Mask.*`).

### Tracker patterns and Track Mask (Compositing page)
The least-squares move / turn / scale of several tracked patterns uses the closed-form similarity fit of Umeyama
(1991), `similarityFromPoints()` in `src/compositing/tracking/Homography.cpp`. The Track Mask of the Planar Tracker
only decides which patches are used; the idea is the same as the mask input of the Planar Tracker nodes of Natron and
Fusion. No code was taken from either.

### Modifiers, parameter links and expressions (Compositing page)
`src/core/Modifiers.*`, `src/core/Expression.*`, `src/core/CompLinks.*`. The design was studied in Blender (GPL-2.0-or-later):
drivers evaluated with a restricted, side-effect-free "simple expression" language compiled once and run many times,
and the F-Curve Noise and Cycles modifiers (strength, scale, depth, repeat modes with offset); and in Natron
(GPL-2.0-or-later): parameter expressions and links between nodes. Control names follow the Modifiers, Connect To and
Publish features of the public Fusion reference manual. The expression evaluator, the noise functions and the link
resolving are written for Kinoklip; no code was taken from any of these projects.

### Groups, macros, instances and underlays (Compositing page)
`src/core/CompGroups.*`, `src/core/MacroFiles.*`. The design was studied in Natron (GPL-2.0-or-later): group nodes with
published parameters that are saved as reusable plugins (PyPlugs), and in Blender (GPL-2.0-or-later): node groups with
an interface of exposed sockets. Names and behaviour follow the Group, Macro, Underlay and Instance features of the public
Fusion reference manual. The graph stays flat with a group as a container, a macro control is a number on the macro node
that the inner parameter is connected to (spec 119); the code was written for Kinoklip and nothing was taken from the
projects above.

### Compositing colour nodes and Vector Motion Blur (Brightness Contrast, Alpha Multiply / Divide, Channel Mapper, Color Curves, Hue Curves, Custom Tool)
`src/render/CompColorMath.*`, `GlCompColor.*`, `CompWarpMath.*` (vectorMotionBlur), `src/core/Expression.*` (compilePixel(), toGlsl()). The control sets follow the public Fusion reference manual in outline. The ideas were taken from the documented behaviour of Blender's compositor nodes (Bright / Contrast, Alpha Convert, RGB Curves, Hue Correct, Vector Blur; GPL-2.0-or-later) and Natron's shuffle, colour-matrix and expression nodes (GPL-2.0-or-later): a per-pixel formula language compiled once and run on the CPU and, as generated GLSL, on the GPU; a channel matrix; curves baked into tables; a blur that averages samples along a motion vector. The code was written for Kinoklip and nothing was copied from those projects (their source files were not read for this batch, only their documentation).

### Compositing: particles (spec 129)
`src/render/CompParticles.*`, the Particles nodes of `src/core/NodeRegistry.cpp`. The control sets follow the public Fusion reference manual in outline (pEmitter, pGravity, pTurbulence, pMerge, pRender). The force model was checked against Blender's force fields (`source/blender/blenkernel/intern/effect.cc`, GPL-2.0-or-later): a constant force is a strength along a direction, and the turbulence force is smooth noise per axis remapped to -1..1, sampled at the particle position scaled by a size, multiplied by the strength and added to the velocity. Only the force-field part of that file was read; the code (SplitMix64 random numbers, 3D value noise, the emitter, the drawing) was written for Kinoklip and nothing was copied.

### Compositing: 3D (spec 130)
**Extruded, bevelled Text3D (1.13, spec 130.12).** `src/render/TextMesh3D.*`, `third_party/earcut/` (vendored, unchanged). **earcut.hpp** ([mapbox/earcut.hpp](https://github.com/mapbox/earcut.hpp), ISC licence, copied to `third_party/earcut/LICENSE`, GPL-compatible; the polygon triangulation with holes used for the front and back caps; header only). Studied for the method: three.js `ExtrudeGeometry` (MIT; the outline is walked once per bevel step, every vertex moved along its miter vector, side walls and caps built separately) and Blender's text-to-curve extrude / bevel (GPL; bevel depth and offset, a profile that is round or a chamfer); no code of either was copied. The nesting of outlines into letters and holes, the inset check that halves a bevel too wide for thin strokes, the profile with exact normals and the per-part meshes were written for Kinoklip.

`src/render/CompScene3D.*`, the 3D nodes of `src/core/NodeRegistry.cpp`. The control sets follow the public Fusion reference manual in outline (Image Plane 3D, Shape3D, Text3D, Merge3D, Camera3D, the four lights, Renderer3D). The transform maths was checked against Natron's Card3D (openfx-misc, GPL-2.0-or-later, `Card3D/Card3D.cpp`): a node's matrix is translate x rotate x scale (the rightmost acts first), the XYZ rotation order is Rz x Ry x Rx, and the camera's field of view comes from the ratio of the film back width to the focal length (`a = hAperture / focalLength`), which Kinoklip uses for Camera3D's Focal Length (36 mm film back). Only the transform and camera parts of that file were read; the rasterizer (clipping against the near plane, edge functions with a top-left rule, perspective-correct interpolation, Lambert and Blinn-Phong shading) is textbook graphics written for Kinoklip and nothing was copied.

### Compositing: Paint (spec 131)

### Audio: loudness range, standards and Normalize (spec 134)
`src/render/LoudnessMeter.*` (loudness range), `src/render/LoudnessStandards.*`, `src/render/AudioNormalize.*` (`measureMix`), `src/ui/dialogs/NormalizeMixDialog.*`, `src/ui/audio/LoudnessPanel.*`, the Normalize audio to option of `src/export/ExportJob.cpp`. The loudness range method (a histogram of the short-term values above the -70 LUFS gate, a relative gate 20 LU below their energy mean, the 10th and 95th percentile, the percentile picked as the first bin whose running count passes `(n - 1) * p + 0.5`) was studied in [libebur128](https://github.com/jiixyj/libebur128) (MIT, `ebur128/ebur128.c`, `ebur128_loudness_range`, read 2026-11-19) and in EBU Tech 3342; the code was written for Kinoklip, none copied. The standards' targets are the published values (EBU R128 -23 LUFS, ATSC A/85 -24 LKFS, -14 LUFS for streaming, -16 LUFS for podcasts). The control set follows the public Resolve / Fairlight manual in outline.

### Codecs and patents
FFmpeg in the bundles is configured with `--enable-gpl --enable-version3` and without
`--enable-nonfree`, so no non-redistributable component (such as fdk-aac) is included; AAC is
encoded by FFmpeg's own native encoder. H.264 (x264, OpenH264), H.265 / HEVC (x265) and AAC are
covered by patents in some countries. Kinoklip is distributed free of charge as open-source software;
whether a patent licence is needed to use these formats depends on the user's country and use, and
is the user's responsibility. Builds for repositories that exclude patented codecs (for example
Fedora or Flathub) would take these codecs from the system or a codecs extension instead of
bundling them.

**Normalize audio to: look-ahead true-peak limiter and measured correction pass (1.11).** `src/render/TruePeakLimiter.*`, `src/render/AudioNormalize.cpp` (`planNormalize`). Studied: FFmpeg's `loudnorm` filter (LGPL-2.1-or-later; two-pass mode: measure the input, apply the offset linearly, and when the true peak would pass the ceiling fall back to limiting; the idea of re-measuring the limited result and correcting the gain) and the published look-ahead limiter design (minimum filter over the look-ahead window, then a moving average as long as the window, as in the usual "brick-wall look-ahead limiter" write-ups). No code was copied; the limiter and the secant correction were written for Kinoklip.

**Gate / Expander, key (side chain), De-Esser and Dialogue Leveler (1.11, spec 136).** `src/render/Dynamics.*` (gate section, key filters, external key), `src/render/AudioMixerGraph.cpp` (key scheduling), `src/render/DeEsser.*`, `src/core/MixerOps.cpp` (loop check). Studied for the controls and the behaviour: the public Blackmagic Fairlight documentation (Dynamics window with Expander / Gate, Compressor, Limiter and the key input; Dialogue Leveler; De-Esser), x42-dynamics ([x42/dpl](https://github.com/x42/dpl) and x42's expander; GPL-2.0-or-later: gate with hysteresis, hold and range, key filters), ZAM-plugins ([zamaudio/zam-plugins](https://github.com/zamaudio/zam-plugins); GPL-2.0-or-later: ZamGate, ZamComp side-chain input) and Calf ([calf-studio-gear](https://github.com/calf-studio-gear/calf); LGPL-2.1-or-later: gate, expander and the split-band Deesser). **Chorus, Flanger, Distortion, Stereo Width and the Reverb with Pre-delay, Decay and room presets (1.11, spec 138).** `src/render/ModFx.*`, the processors in `src/render/AudioClipEffects.cpp`, the catalogue in `src/core/BuiltinAudioEffects.cpp`.
