# Contributing

1. Read [coding-style.md](coding-style.md) before writing code: naming, doc comments on every
   public class and function, file headers, and a `readme.md` with a **How to extend** section in
   every module directory.
2. Read [docs/archive/plan.md](archive/plan.md) (the original architecture plan) for the module contracts, and
   [behavior-spec.md](behavior-spec.md) for how each feature must behave.
3. Shortcuts are never hard-coded: they go through the `ActionRegistry` and the keymap profiles.
   The Resolve keymap is generated by `scripts/keymap-resolve-windows.py`; do not edit
   `resources/keymaps/resolve-windows.json` by hand.
4. Follow the [clean-room policy](clean-room.md): nothing from Resolve or other Blackmagic products
   (code, icons, images, presets, documentation text, screenshots) is used or copied, Resolve is
   never installed or inspected, and pages and features use our own names (generic words like Cut,
   Edit, Color, Deliver, Media are fine; "Fusion", "Fairlight" are not). Every new asset gets a row
   in [attribution.md](../attribution.md) with its author and licence.
5. Write tests for logic (`tests/<area>/test_*.cpp`) and run them before committing; see
   [building.md](building.md).
   After changing [roadmap.md](roadmap.md) or [effects-library-status.md](effects-library-status.md),
   run `python3 scripts/status.py`: it redraws the status picture and the table in the readme
   (`--check` runs as the ctest `check_status`).
6. Format before committing: `scripts/format.sh` (clang-format, `--check` for CI).
7. **Privacy:** never add code that sends or collects user data without explicit, per-use consent.
   Kinoklip has no telemetry, analytics, automatic crash reports or update pings, and makes no
   network requests; see [privacy.md](privacy.md).

## Memory leaks
Kinoklip plays long sessions (hours of editing, slow-motion playback, full-screen toggles, page
switches), so a leak is a bug that ends in an out-of-memory kill (GitHub issue #8). Two checks
catch them; run both **before every release** and **after any change in playback, render, media
or viewer code** (`src/playback`, `src/render`, `src/media`, `src/ui/viewer`):

1. **LeakSanitizer:** `podman exec -w "$PWD" kk-arch scripts/check_leaks.sh [build dir] [ctest -R pattern]`.
   It configures `build-asan` (`-DKK_SANITIZE=address`; `address,undefined` also works, any
   build type, ccache), builds the application and the selected tests, runs them with
   `detect_leaks=1` and `scripts/lsan.supp`, and prints, per test, every leak with its first
   frames in our code (`src/`, `tests/`). The exit code is 1 on a leak, a sanitizer error or a
   failed test. Without a pattern it runs the tests that own memory (media cache, decoders,
   playback engine, viewer, compositing, soak: the list is `DEFAULT` at the top of the script);
   `all` runs every test, which takes many hours under ASan. Logs: `<build dir>/leak-logs/`
   (`<test>.<pid>` per process, `summary.txt`, `ctest.log`).
2. **Memory soak:** `ctest -L soak` (`tests/playback/test_memorysoak.cpp`). It plays a generated
   1080p clip through cycles of play, stop, seek, speed 100 / 25 / 12.5 %, full-screen viewer and
   window resize, every page and a second timeline, and checks that RenderedFrame objects,
   output slots (GL textures), decoders and cached tiles return to their values after a warm-up
   and that process memory (VmRSS) grows by less than 250 MiB. `KK_SOAK_CYCLES=200` runs it
   overnight, `KK_SOAK_LOG=1` prints the counters after each cycle.

**Reading the output.** A record such as `Direct leak of 4096 byte(s) in 1 object(s)` is memory
nobody can reach any more; the lines under it are the call stack that allocated it, our frame
first. Fix the owner (a missing `delete`, a `QObject` without a parent, a `shared_ptr` cycle, a
frame kept in a queue); `Indirect` leaks vanish with their direct parent. `still reachable`
memory is not reported (growth of reachable memory, such as a cache without a limit, is what the
soak test sees). A failing soak line names the counter and its two values.

**Suppressions** (`scripts/lsan.supp`) are for third-party code only: Qt platform plugins,
fontconfig, Mesa / llvmpipe, libva, FFmpeg hardware device initialisation, glib, dbus, whose
stacks contain no Kinoklip frame. Add `leak:<library or function>` with a comment saying what
it is and why it is not ours. Never suppress a Kinoklip function or file: fix the leak.

## Reporting bugs
The easiest way: in Kinoklip, **Help > Report a Bug or Inconsistency...**. Choose a bug, something
that works differently from DaVinci Resolve, or an idea; the dialog shows exactly which version and
system info it would add, and opens GitHub's report form in your browser with or without it. You
then describe what you did, what happened and what you expected, and submit it there. Without the
app, use [New issue](https://github.com/SeniorMatt/kinoklip/issues/new/choose) on GitHub; the forms
live in `.github/ISSUE_TEMPLATE/` (`scripts/check_issue_forms.py` checks them).

## Translating Kinoklip
The interface is available in English (the source language), German, Spanish, Russian and
Ukrainian. The translations are Qt Linguist files, one per language, in
`resources/translations/kinoklip_<code>.ts`; they are compiled into the application at build time
(`lrelease`, CMake option: Qt6 LinguistTools; without it the application is built English-only).
Open a file in Qt Linguist (`linguist`) or any text editor and fill in the `<translation>`
elements; an entry marked `type="unfinished"` is a draft that was not reviewed yet, remove the
mark when it is right. Keep the placeholders (`%1`, `%2`, `%n`), keep the `&` accelerator
before a letter that no other entry of the same menu uses, and use the words of the translated
DaVinci Resolve and the Kdenlive / Shotcut interfaces for the same language where they have one.

- **Update the strings** after changing the sources: `cmake --build build --target update_translations`
  (runs `lupdate` over `src/` into every .ts file). Translatable text is written `tr("...")`
  (`QCoreApplication::translate("Context", "...")` outside a QObject, `QT_TRANSLATE_NOOP` in
  static tables, `%n` in counts so that every language gets its plural forms). Object names,
  settings keys, file formats, codec names, log lines (`kk.*` categories) and command names
  stay English.
- **Add a language:** copy an existing file to `kinoklip_<code>.ts` and change `language="..."`
  in its first line, run `update_translations`, translate, add the code and the language's own
  name to `languages()` in `src/core/Translations.cpp`, and the Qt translations of the language
  (`qtbase_<code>.qm`) to the loop in `scripts/package_linux.sh`. Build, start with
  `kinoklip --lang <code>` (or `KK_LANG=<code>`), look at every page and at Preferences.
- **Choose the language:** Preferences > User > UI Settings > Language (restart needed), the
  command line `--lang <code>` or the environment variable `KK_LANG` for one run.
- **Check:** `test_translations` installs a pseudo language that wraps every translated text in
  `[!! ... !!]`, builds the window, the pages and the main dialogs and fails for every visible text
  that is not wrapped, i.e. that bypasses `tr()`. Texts that stay the same on purpose (brand
  names, codecs, units) go into `tests/app/translation_allowlist.txt`.
