Kinoklip 0.1.0-alpha.4 - fourth alpha: fixes for the alpha.3 feedback (Wayland, Intel GPU decoding, logs) plus the first v2 features (timeline tabs and compound clips). Still an alpha: expect bugs, keep backups.

## Download and run (Linux x86_64)
1. Download `Kinoklip-x86_64.run`.
2. Make it executable: right-click > Properties > "Is executable", or `chmod +x Kinoklip-x86_64.run`.
3. Double-click it (or run `./Kinoklip-x86_64.run`). The first start unpacks into `~/.cache/kinoklip`; later starts are fast.

Needs: x86_64 Linux, OpenGL 3.3, `zstd` + `tar` (or `bsdtar`). Wayland and X11. `kinoklip-x86_64.tar.zst` is the same app as a portable folder; `SHA256SUMS.txt` has checksums.

## Fixes since alpha.3
**Drag and drop / Wayland**
- Dropping media into the empty area above the top video track or below the last audio track now creates a new track there (like Resolve) instead of being refused.
- Files dragged from Dolphin or the desktop onto the media pool or straight onto the timeline import reliably on Wayland (works around a [Qt](https://www.qt.io) file-transfer-portal problem).
- No more "This plugin supports grabbing the mouse only for popup windows" warnings (panel splitters and the menu bar no longer grab the mouse).
- Window resizing: viewers re-render once when the size settles instead of at every step, showing the last frame scaled meanwhile.
- Keyframes panel: labelled Float/Dock button, double-click its header to float or dock, drag the header out to tear it off; splitter handles highlight on hover.

**Intel GPU decoding and logs**
- Hardware decoding is serialised per GPU device (the likely cause of "Failed to sync surface" on Intel); a failed frame is retried once, then that clip continues in software decoding without dropped frames or garbage.
- One clear log line per clip says which decoder is used (e.g. "decoding clip.mp4 (h264 1920x1080) with VAAPI (iHD ...)"); one summary line for hardware encoders.
- No more CUDA / NVENC / QSV / UDTA noise in the terminal.
- `KK_PLAYBACK_STATS=1` now prints a line every second while playing and a summary when playback stops. Tip: when not started from a terminal, Qt logs to the system journal; use `QT_FORCE_STDERR_LOGGING=1` to force the terminal.
- See `docs/hw-decode-test.md` in the repository for a short test procedure.

## New (first v2 features)
- **Multiple timelines** per project: File > New Timeline (Ctrl+N), duplicate, rename, delete; timelines appear in the media pool; each can follow the project settings or have its own resolution and frame rate.
- **Timeline tabs** (on by default): open timelines as tabs above the tracks, reorder, close, right-click menu. Preferences > Editing can switch to a drop-down instead.
- **Compound clips**: Clip > New Compound Clip collapses the selection into one clip (with linked audio); Open in Timeline edits it in its own tab (all instances update); Decompose in Place restores the clips.
- **Nested timelines**: drag a timeline from the media pool into another timeline.
- Projects are saved in a new format version; older projects open unchanged.
- Note: Ctrl+N is now New Timeline (as in Resolve); New Project has no default shortcut.

## Known limitations
- Colour grading, compositing and audio pages are not built yet; masks are in progress.
- Resizing on Wayland may still be heavy because the OpenGL viewers make Qt draw the whole window with OpenGL; feedback welcome.
- Intel VAAPI paths are still unverified on real Iris Xe hardware.
- Decompose in Place drops the compound clip's own transform/effects and refuses speed changes.
